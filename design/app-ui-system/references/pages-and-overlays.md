# Pages and overlays

## Page

- The "New …" action stands in the title row, at the right, at every width, never in a toolbar.
- A main working view (the profile names it) keeps everything done there in place: a dialog, a drawer or expanding in place. Only the navigation changes the page. If it shows a current period, it always shows the current one; the full set for filtering and export lives on its own page.

## Dialog or drawer

Choose by the main function:

- Entering or editing data: a dialog, centred.
- Reading with occasional editing: a drawer.
- Creating is always a dialog.

Every overlay:

- only the close button at the top right;
- head and foot always visible, only the body scrolls;
- fits down to the smallest viewport the profile lists;
- on the phone full screen, with its actions at the bottom;
- a light dim without blur behind it;
- Escape closes it, and focus returns to the element that opened it.

## Records

- Main records are pages; small items handled in passing open in a drawer (the profile lists which is which).
- A record page: the next step and "Edit" in the head, rare commands behind "⋯".
- Pages of one kind are built alike (one record page looks like the others). A list with a breakdown: list two thirds, breakdown one third, stacked below the width the profile sets.

## One way to edit a record

- Master data has one form per kind, used for creating and for editing, always in the same dialog, opened from the list and from the record page.
- Fields that cannot change after creating are the only difference, and they say why.
- An item that opens in a drawer is edited in that drawer.

## Times and durations (if the app edits time spans)

- Wherever a time span is edited: duration first, then start, then end.
- A running item stays editable; the form freezes the value of the moment while the item keeps running.
- One time field understands the common ways to type a span (for example "9–12:30", "1:30", "90 min").

## Blocks

A block is a heading line (a tab switcher can be that line) with a surface of its items under it. Blocks side by side share the height and baseline of their heads.
